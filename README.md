# SKYBREAK ARENA — ブラッシュアップ版

[ブラウザでゲームをプレイ](https://sugark615-creator.github.io/skybreak-arena/)

5体からファイターを選ぶ、スマホ横画面対応の2D対戦アクションです。

## 遊び方

起動画面の「タップしてスタート」（PCはEnter／Space）からファイター選択へ進みます。起動時に勝手に対戦やマッチングは始まりません。選択画面の「タイトルへ」で戻れます。
画像の読み込み中はスタートを待機し、失敗時には再読み込みボタンが表示されます。起動画面でも音ON/OFFを切り替えられます。

キャラクター、対戦相手、CPUの強さを選んで対戦開始。3カウントの後、3分・3ストック戦が始まります。
攻撃でダメージを蓄積させて相手を場外へ吹き飛ばします。時間切れは残りストック、次にダメージで勝敗を判定します。
「CPU同士のデモ対戦」では、ランダムに選ばれた異なる2体の対戦を観戦できます。選択中のCPU難易度が双方に適用され、結果画面からデモを再戦できます。
「オンライン対戦」では、同じタイミングで待機しているプレイヤーと自動でマッチングします。アカウント名や合言葉の入力は不要です。

- 左スティック / A・D・左右キー：左右移動
- スマホは左の丸いスティックを指で倒して移動します。斜めにも動くノブは円の内側に収まり、中央に戻す・指を離すと停止します。ジャンプは右のXボタンです
- Aボタン / J：近接攻撃。長押しで3段コンボ
- Bボタン / K：通常ショット。MAXゲージ100%時は最大必殺技に切り替わります
- Xボタン（右の上側） / Space・W・上キー：ジャンプ
- Yボタン（右の左側） / L：ガード
- CPU戦のⅡボタン / P・Esc：一時停止。音量調整・選択画面へ戻る操作もここにあります
- オンライン戦の右上「退出」/ P・Esc：退出確認。確定すると相手の勝利となり、キャラクター選択へ戻ります。確認中も対戦は進行します
- ♪：音をオン／オフ

ゲージは攻撃命中・被弾・ガードで蓄積します。MAX発動で全消費し、MAX自身の命中では攻撃側ゲージを補充しません。
落下後は途中までのゲージを保持、再戦時はリセットします。メニューの選択・難易度・音量はこの端末のブラウザーに保存します。

近接攻撃の円弧はキャラクターの向きに合わせて左右反転し、攻撃の途中で向きを変えた場合も追従します。
ジャンプは従来より約3割高く、空中の左右操作も反応を良くしています。上昇中だけ重力を軽くし、落下時・被弾硬直中の重力、地上の移動速度、各キャラクターの空中ジャンプ回数は維持します。

## ファイター

| ファイター | 特徴 | 通常B技 | MAX |
|---|---|---|---|
| アーク | 扱いやすい速度と電撃 | サンダーショット | マックスサンダー |
| ジェット | 最速の移動・速い連射、軽い一撃 | プラズマショット | スターレーザー |
| ミスト | ゆっくり落下、地上＋空中3回ジャンプ | スターショット | スタークラッシュ（3方向） |
| ブリック | 重い一撃・吹き飛びにくさ、控えめな速度 | ボルトショット | ファーネスブレイク |
| スプリング | 高いジャンプと速い移動 | ウィンドショット | スカイサイクロン |

アーク（雷の結晶ゴーレム）・ジェット（仮面のエアスケーター）・ミスト（雲の精霊）は新規デザインで、各12ポーズの透過画像を使用します。ブリック・スプリングは従来のデザインです。
旧キャラクター画像は保管されており、現行のゲームとビルドからは参照しません。

## 画面の表記

日本のゲームでなじみのある日本語・カタカナを基本とし、CPU・MAX・OK・VS、A/B/X/Y、キーボードのキー名、英語ロゴは維持します。
「勝利」「敗北」「引き分け」「再戦」「必殺技OK！」など、操作や結果に関わるメッセージを整理しています。通常のB技はいつでも使え、ゲージ満タン時もB/Kを押して必殺技を発動します。
自分・相手の表示はHUDとキャラクター頭上で統一します。CPU戦は「自分／CPU」、オンラインは「自分／相手」、デモは「CPU 1／CPU 2」です。
表示名だけを変更し、保存設定・対戦通信・画像参照のキャラクターID（arc、jet等）は変更しません。

## 音楽と効果音

- 起動画面・キャラクター選択・マッチング待ち・結果画面：ユーザー提供の「ホーム画面」から音声のみを取り出した `media/menu-theme.m4a`（ステレオAAC、約2分59秒、約4.2MB）をループ再生します。元のMP4は変更せず、音声の再圧縮もしていません。
- 対戦中：これまでのユーザー提供曲 `assets/battle-theme.mp4` を使います。曲頭0.75秒と曲末2.83秒の無音を再生範囲から外します。読み込み失敗時はオリジナル曲「IGNITION」（`assets/ignition.wav`）へ切り替わります。
- BGMは1つの再生プレーヤーを共有して画面に応じて切り替え、2曲同時には流しません。メニュー内の移動では曲を継続し、対戦との切り替えでは曲頭から再生します。全曲を2本分メモリーへ展開しない方式です。
- 選択・決定・戻る操作には、それぞれ短い効果音が鳴ります。効果音の際はBGMを短く下げます。最初のタップ・クリックから音声が有効になります。
- 一時停止中とタブ非表示中はBGMを止め、復帰・再開時は途中から再生します。選択・待機・結果画面の「音 ON/OFF」、対戦中の♪ボタンと音量設定はBGM・効果音共通です。

## スマホでテスト

Macと同じWi-Fiに接続し、サーバー起動時に表示される Network URL をスマホで開きます。
Macを起動したままにしてください。ゲームは横向き、選択メニューは縦向きでも操作できます。
端末の縦向き固定は解除してください。CPU戦は縦向き・タブ非表示・別アプリへの移動時に自動で一時停止します。
オンライン戦は一時停止できません。縦向きの案内からも退出でき、タブ非表示・別アプリへの移動時は押しっぱなしの入力を解除します。
音声は画面をタップする、キャラクターを選ぶ等の操作後に有効になります。全画面／横向き固定はブラウザーが対応する場合のみ有効です。

スマホの操作は左の円形スティック＋右のひし形4ボタンです。上X：ジャンプ、右A：攻撃、下B：通常技／MAX、左Y：ガード。ボタンは直径52〜56px、スティックは約101〜118pxのコンパクト配置で、画面端・ホーム操作部分から余白を取ります。
スティックは最初に触れた指を追跡し、円の外まで指を動かしても方向を維持します。離す・タッチ中断・メニュー移動時には中央へ戻り、入力を解除します。右の攻撃・ジャンプとは独立して同時操作できます。
表示領域の高さ・位置をゲーム画面と操作ボタンで共通化し、対戦中のドラッグによるページ移動を抑えます。メニュー内のスクロールは維持します。
iPhone実機で報告された「対戦中に画面が上に動く」症状は再現条件が不明です。Chromeのスマホ表示・複数指操作と表示領域変化の模擬テストは行いますが、iPhone実機での再確認が必要です。

## 起動と保存

必要に応じて `npm install` を実行し、以下で起動します。

```sh
npm run dev -- --host 0.0.0.0 --port 5196 --strictPort
```

ビルド：`npm run build`。配信対象は `dist/` です。
主な実装は `main-2d.js`、`polish.css`、`battle-audio.mjs`、`index.html`。
旧3D版の `main.js` と旧CSSは保管用で、このバージョンからは読み込みません。

## GitHub Pages

公開リポジトリの `main` ブランチへプッシュすると、`.github/workflows/deploy-pages.yml` がビルドと公開を実行します。
GitHubのリポジトリ設定では、PagesのSourceを `GitHub Actions` にします。

## 確認

`node verify-polish.mjs` でインストール済みChromeを使い、PC・スマホ横画面の5体選択、B/MAX、ゲージ消費、
一時停止、発射方向・半径を反映する命中判定、ジャンプ回数、結果画面を確認します。
テスト用状態操作はテストが通信を差し替えて追加するもので、ゲーム本体には含みません。
実機iPhone/Androidでの音声・全画面は端末ごとの確認が必要です。

## オンライン対戦（開発中）

画面はGitHub Pages、マッチングと対戦通信はCloudflare Workers／Durable Objectsで動作します。
対戦サーバーは `online/worker.js`、ブラウザー側の接続処理は `online/client.js`、共通メッセージ定義は `online/protocol.js` です。

ローカルで対戦サーバーを起動する場合：

```sh
npx wrangler dev --config online/wrangler.jsonc
```

ゲーム側はlocalhostの場合、自動的に `ws://127.0.0.1:8787/match` へ接続します。公開ビルドでは環境変数
`VITE_MATCHMAKER_URL=wss://<WorkerのURL>/match` を指定します。GitHub Actionsでは同名のRepository secretから読み込みます。

通信では匿名の一時IDだけを使用し、メールアドレスやプレイヤー名は保存しません。ホスト側が当たり判定・ダメージ・残機・勝敗を決定し、ゲスト側へ毎秒30回同期します。

自分の接続が切れた場合は「通信が切れました」と表示し、「次の対戦」から相手を探し直せます。相手が退出・切断した場合は自分の勝利になります。
検索中の接続失敗は「もう一度探す」で再試行できます。

接続処理の回帰テスト：`node --test online/protocol.test.mjs online/client.test.mjs`。
音声の切り替え・ミュート・読み込み遅延・選択音の単体テスト：`node --test battle-audio-player.test.mjs`。
実ブラウザーの音声出力・初回操作・メニュー／対戦／結果・ループ・読み込み失敗：`node menu-audio.e2e.test.mjs`（ゲームサーバー起動後）。
タッチ操作・表示領域の単体テスト：`node --test touch-controls.test.mjs game-viewport.test.mjs`。
近接攻撃の左右反転・描画状態保持：`node --test melee-effect.test.mjs`。
5体のジャンプ・着地・空中移動、左右の3段コンボ、実Canvasの反転描画、A/X操作：`node movement-combat.e2e.test.mjs`（ゲームサーバー起動後）。
日本語・カタカナ表記、保存IDの維持、勝敗・必殺技・役割表示、小画面レイアウト：`node japanese-ui.e2e.test.mjs`（ゲームサーバー起動後）。
起動画面の6画面サイズ、ロード待ち、キーボード入力、選択の保持、画像失敗からの再試行：`node title-screen.e2e.test.mjs`（ゲームサーバー起動後）。
スマホの複数指操作・表示領域変更・メニュースクロール：`node mobile-controls.e2e.test.mjs`（ゲームサーバー起動後）。
ローカルのゲームと対戦サーバーを起動したうえで、`node online/lifecycle.e2e.test.mjs` を実行すると、退出・キャンセル・再検索・切断時の表示をPC／スマホ画面で確認できます。
ゲームのURLが異なる場合は環境変数 `ARENA_URL` で指定します。テストはブラウザーの応答にだけ検証用コードを加え、公開ファイルは変更しません。
